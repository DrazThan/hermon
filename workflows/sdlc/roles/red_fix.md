# Correct the independent test freeze

Read block_reason, the accepted RED reference, the approved plan and the existing tests. Reproduce the reported defect. Correct only the justified acceptance-test or fixture defect within the configured test paths, preserving the approved behavior and planned test IDs. A requirement change is scope_change and requires a revised plan and fresh Owner GO.

Do not change production code or weaken an assertion merely to make GREEN pass. Execute lint and the configured tests again and establish behavioral RED for all independently expected new failures. If GREEN already committed production changes, the expected tests may pass at HEAD; that alone is not a block. The hub evaluates `tests_fail` against pre-implementation production: production paths changed since the intake base are restored to the base version (recorded as `base` in the RED tag's note: `git notes --ref=hermon show <red ref>`), with your test paths from HEAD. To reproduce, restore those production paths from the base, run the tests, then return with `git checkout -f HEAD` and leave the worktree clean before committing. Commit the correction, preserve the original evidence and explain exactly what changed and why in the result summary. The hub writes a superseding RED tag with history retained and reruns GREEN. Corrections are bounded by max_runs; an unresolved defect must remain visible as a block.
